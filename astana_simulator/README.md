# Аким на 5 часов

**AI-симулятор управления городом для кейса HackAlem AI.** Пользователь выбирает пять городских мероприятий в рамках бюджета 100 условных единиц и видит, как решения меняют показатели пяти районов и итоговый Astana Quality of Life Score. Приложение предназначено для команд хакатона, жюри и всех, кто хочет сравнить управленческие сценарии на одинаковых исходных данных.

Проблема кейса — ограниченный бюджет приходится распределять между транспортом, озеленением, социальной инфраструктурой, безопасностью и городскими сервисами. Симулятор делает последствия выбора проверяемыми: числа рассчитываются детерминированной моделью, а OpenAI по отдельному запросу готовит текстовый разбор сильных сторон, рисков и компромиссов. **Все районные показатели синтетические и не описывают фактическое состояние Астаны.**

## Что реализовано

- Единый бюджет **100 ед.** (1 ед. = 10 млн ₸) и исходный Score **52,56 / 100** для всех пользователей.
- Основной режим с каталогом **14 мероприятий**: пять уникальных решений, не более двух в одном направлении; районные и общегородские меры, стоимость, лаги, эффекты, конфликты и три фиксированные синергии.
- Проверка бюджета и правил до расчёта; ошибки объясняют, что нужно исправить. Выбранные меры можно удалить или переназначить другому району.
- Интерактивная карта пяти районов, карточки их показателей, сравнение «До / После», маркеры решений, графики и объяснение формулы Score.
- Дополнительный режим распределения бюджета по пяти направлениям с отдельной непрерывной учебной моделью. Его результаты нужно сравнивать отдельно от режима каталога.
- Экспорт сценария и рассчитанных результатов в JSON. При наличии ключа OpenAI — экспертный отчёт на русском языке через **`gpt-4o-mini`**. Без ключа расчёт и визуализация работают.

## Как работает решение

1. Приложение загружает локальный синтетический датасет: пять районов, десять показателей, доли населения, каталог мер и бюджет.
2. Пользователь выбирает режим. В основном режиме он добавляет пять мер в план; для районной меры указывает район, для городской охват задаётся автоматически. Район можно выбрать на карте или в карточке.
3. `validate_decisions` проверяет число и уникальность мер, бюджет, направления, адресатов и несовместимости. При допустимом плане `simulate_decisions` применяет эффекты с учётом лага на горизонте **8 кварталов**, синергии и ограничение показателей диапазоном 0–100.
4. `score_indicators` рассчитывает районные баллы и итог: `Score = clip(0,7 × средний взвешенный балл районов + 0,3 × балл слабейшего района − Ncrit, 0, 100)`, где `Ncrit` — число показателей строго ниже 40.
5. Интерфейс показывает результат, изменение относительно базы, слабые показатели и вклад мер. Кнопка запуска подтверждает сценарий. AI-отчёт отправляется в OpenAI **только по отдельному нажатию** и не меняет числовой Score.

Во вкладке **«Планирование»** находятся каталог и пять слотов решений, во вкладке **«Карта Астаны»** — ситуационный центр, во вкладке **«Результаты»** — числа, методика и исходное состояние города.

## Технологии

| Компонент | Реализация |
| --- | --- |
| Язык и интерфейс | Python 3.12, Streamlit 1.64.0, HTML/CSS для оформления |
| Расчёты и графики | Стандартная библиотека Python, pandas 3.0.6, Plotly 7.1.0 |
| Карта | Pydeck 0.9.3, локальный GeoJSON контуров OpenStreetMap; необязательная уличная подложка CARTO |
| AI | OpenAI Python SDK 3.19.0, Chat Completions API, модель `gpt-4o-mini` |
| Конфигурация | `python-dotenv` 1.2.3 и переменная окружения `OPENAI_API_KEY` |
| Проверки | pytest и Streamlit AppTest из `requirements-dev.txt` |

NVIDIA API и другие AI-провайдеры в симуляторе не используются.

## Архитектура

Симулятор целиком находится в папке `astana_simulator/`. Корневые `app.py` и `requirements.txt` репозитория относятся к другому проекту.

| Файл или папка | Назначение |
| --- | --- |
| `streamlit_app.py`, `app.py` | Основной интерфейс и альтернативная точка входа |
| `src/data.py` | Исходный датасет, бюджет, веса, меры и синергии |
| `src/model.py` | Чистая проверка решений, моделирование и расчёт Score |
| `src/planner.py`, `src/catalogue.py` | Управление планом и карточки мероприятий |
| `src/geography.py`, `src/map_view.py` | Подготовка геометрии, цвета и события интерактивной карты |
| `src/landing.py`, `src/game_ui.py`, `assets/` | Первый экран, HUD, карточки районов и стили |
| `src/ai.py` | Загрузка ключа, запрос OpenAI и обработка ошибок |
| `data/astana_districts.geojson` | Локальные контуры пяти районов |
| `tests/` | Проверки модели, UI, карты и AI-контракта без платных запросов |

Данные и правила отделены от интерфейса: карта и AI-отчёт получают уже рассчитанный сценарий, а не вычисляют собственный Score.

## Установка и запуск

Нужен **Python 3.12**. Команды выполняются из папки симулятора. На Windows PowerShell:

```powershell
git clone https://github.com/BAITC-Hacks/hack-a935f8e0-mine.git
cd hack-a935f8e0-mine
git switch codex/astana-simulator
cd astana_simulator
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py
```

На Linux / macOS после перехода в `astana_simulator/`:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run streamlit_app.py
```

Откройте адрес, который напечатает Streamlit (обычно `http://127.0.0.1:8501`). Для локального расчёта ключ API не требуется. `app.py` внутри `astana_simulator/` запускает тот же интерфейс. `requirements-lock.txt` содержит снимок проверенного окружения Windows / Python 3.12.

**Необязательный AI-разбор.** Создайте `astana_simulator/.env` на основе `.env.example` и впишите ключ:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

```dotenv
OPENAI_API_KEY=ваш_ключ
```

Перезапустите Streamlit, соберите допустимый сценарий, раскройте **«🤖 Штаб советников · OpenAI»** и нажмите **«Получить AI-разбор»**. Код читает ключ через `os.getenv("OPENAI_API_KEY")`; переменная окружения имеет приоритет перед `.env`. Файл `.env` исключён из Git. Для ответа необходимы доступ к OpenAI API и доступная квота аккаунта.

## Как проверить решение

1. Откройте приложение: на первом экране должны быть бюджет **100 ед.**, пять районов и базовый Score **52,56**.
2. Нажмите **«СОБРАТЬ СЦЕНАРИЙ»** и оставьте режим **«Каталог мероприятий»**. Нажмите **«Загрузить пример»**. Это меры M7, M8 и M10 для Нуры, M12 для всего города и M5 для Сарыарки.
3. Проверьте пять заполненных слотов, расход **95 ед.** и остаток **5 ед.**. Результат примера — **56,54307** до округления в интерфейсе; срабатывает синергия M10 + M12. Нажмите **«Запустить симуляцию»** и откройте вкладки карты и результатов.
4. Удалите меру: план станет неполным, итоговый расчёт и AI будут недоступны. Добавьте её снова. Попробуйте выбрать меру сверх бюджета или конфликтующую с уже выбранной — интерфейс должен объяснить ограничение.
5. При необходимости скачайте JSON. Ключ OpenAI нужен только для проверки текстового отчёта.

Автоматические проверки, без запросов к внешним API:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

## Данные и интеграции

Исходные синтетические показатели, 14 мер и правила находятся в `src/data.py`; локальные копии [условий кейса](docs/case.md) и [датасета](docs/dataset-source.md) сохранены в `docs/`. Их исходные ссылки указаны внутри приложения. Значения районов и Score **не поступают из OpenStreetMap**. Локальный файл `data/astana_districts.geojson` содержит только геометрию пяти районов, собранную из OpenStreetMap через Overpass API; обычный запуск не обращается к Overpass. Сведения об источниках и лицензии ODbL есть в [описании геоданных](data/README.md). Уличная подложка CARTO необязательна и загружается браузером при её включении.

Единственный внешний AI-запрос — к OpenAI API по явному нажатию кнопки. В запрос уходят синтетические данные и рассчитанный сценарий; ключ не включается в JSON-экспорт. Ошибки сети, доступа и квоты обрабатываются в интерфейсе.

## Ограничения

- Это учебная симуляция: показатели, доли населения, эффекты и прогноз Score не являются актуальной городской статистикой или оценкой реальной политики.
- Карта охватывает только пять районов датасета; геометрия OSM не служит подтверждением официальных административных границ. Уличная подложка зависит от интернета.
- Дополнительный режим слайдеров использует авторскую непрерывную модель, поэтому его результаты нельзя напрямую сравнивать с каталогом мероприятий.
- AI-отчёт требует действующего ключа, сети и квоты; его текст может ошибаться, числовой Score определяется только Python-моделью.
- Сравнение команд, случайные городские события и автоматическая презентация решения не реализованы.
