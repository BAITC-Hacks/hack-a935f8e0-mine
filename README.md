
# Аким на 5 часов · Astana Lab

Учебный AI-симулятор управления городом, разработанный для кейса HackAlem AI. Пользователь распределяет ограниченный бюджет, выбирает городские инициативы и оценивает их влияние на **Astana Quality of Life Score**.

## 1. О проекте

При планировании развития города необходимо учитывать транспорт, экологию, социальную инфраструктуру, безопасность и городские сервисы. Ограниченный бюджет заставляет выбирать между инициативами и учитывать различия между районами.

**«Аким на 5 часов»** позволяет исследовать такие решения в интерактивном симуляторе: сформировать план, увидеть изменение показателей и получить AI-разбор сильных сторон и рисков.

Проект предназначен для городских управленцев, аналитиков и пользователей, изучающих принципы городского планирования.

> Показатели, доли населения, стоимость мероприятий и их эффекты — синтетические данные учебного кейса. Результаты симуляции не являются прогнозом реального состояния Астаны.

## 2. Что реализовано

### Каталог городских мероприятий

Основной режим содержит **14 мероприятий** по пяти направлениям:

| Направление | Примеры мероприятий |
|---|---|
| Транспорт | Автобусные полосы, умные светофоры, линия ЛРТ |
| Озеленение и экология | Парк, чистое топливо, ветрозащитные полосы |
| Социальная инфраструктура | Школа и детсад, поликлиника, спортивные площадки |
| Безопасность | Освещение и камеры, безопасные переходы |
| Городской сервис | Платформа обращений, модернизация сетей, аварийные бригады |

Пользователь составляет план из **пяти уникальных мероприятий**. Приложение проверяет бюджет, совместимость решений и ограничения по направлениям.

Для районных мероприятий можно выбрать или изменить район. Городские мероприятия действуют во всех пяти районах.

### Распределение бюджета

Дополнительный экспериментальный режим позволяет распределять средства пятью слайдерами. Доступны готовые варианты:

- «Баланс»;
- «Социальный фокус»;
- «Зеленый город».

Этот режим использует отдельную непрерывную модель влияния финансирования на показатели.

### Карта и результаты

- Интерактивная карта районов Есиль, Алматы, Сарыарка, Байконур и Нура.
- Выбор района на карте или из списка.
- Сравнение состояний «До» и «После».
- Слои районного балла, прироста и критических показателей.
- Карточки районов и подробные таблицы показателей.
- Графики распределения бюджета и изменений по направлениям.
- Отображение синергий и вкладов мероприятий с учётом задержки эффекта.
- Экспорт сценария, расчётов и полученных AI-отчётов в JSON.

### AI-советник

По отдельному запросу модель **GPT-4o mini** формирует разбор:

- сильных сторон сценария;
- скрытых рисков;
- возможных корректировок;
- итогового решения для акима.

Числовые результаты рассчитываются Python-кодом. AI получает готовые данные для объяснения и не участвует в вычислении Score.

## 3. Как работает решение

1. Пользователь знакомится с исходными показателями пяти районов.
2. Выбирает режим: каталог мероприятий или распределение бюджета.
3. Формирует план в пределах **100 условных единиц**.
4. Приложение проверяет допустимость сценария.
5. Расчётная модель определяет новые показатели и итоговый Score.
6. Пользователь изучает изменения на карте, графиках и в таблицах.
7. При подключённом API запрашивает AI-разбор.
8. Скачивает результат в JSON.

В основном режиме действуют следующие правила:

- ровно пять уникальных мероприятий;
- не более двух мероприятий из одного направления;
- общие расходы не превышают 100 единиц;
- для районных мероприятий обязательно назначение района;
- M1 и M3 несовместимы;
- M4 и M7 нельзя размещать в одном районе;
- M5 и M13 нельзя размещать в одном районе.

Горизонт моделирования — **8 кварталов**. Эффект мероприятия уменьшается с учётом его лага:

```text
Реализованный эффект = полный эффект × (8 − лаг) / 8
```

Дополнительно учитываются синергии M1 + M2, M10 + M12 и M5 + M6. После применения эффектов значения показателей ограничиваются диапазоном от 0 до 100.

### Расчёт качества жизни

```text
D_d   = сумма взвешенных показателей района
D_avg = средний районный балл с учётом долей населения
Ncrit = число показателей ниже 40 во всех районах

Score = clip(0.7 × D_avg + 0.3 × min(D_d) − Ncrit, 0, 100)
```

Таким образом, оценка учитывает общий результат города, состояние слабейшего района и критические дефициты.

Исходный Score: **52,55768**.

## 5. Архитектура проекта

Симулятор находится в отдельной папке `astana_simulator/`.

```text
astana_simulator/
├── streamlit_app.py          # Основной интерфейс и сборка приложения
├── app.py                    # Альтернативная точка входа
├── src/
│   ├── data.py               # Исходные данные, веса и каталог мероприятий
│   ├── model.py              # Расчёты и проверка сценариев
│   ├── planner.py            # Добавление, удаление и перенос мероприятий
│   ├── catalogue.py          # Интерфейс каталога
│   ├── game_ui.py            # Панель бюджета, карточки районов и запуск
│   ├── landing.py            # Стартовый экран и обзор районов
│   ├── geography.py          # Обработка геометрии и данных карты
│   ├── map_view.py           # Интерактивная карта
│   └── ai.py                 # Запросы к OpenAI и обработка ошибок
├── data/
│   ├── astana_districts.geojson
│   └── README.md
├── scripts/
│   └── fetch_districts.py    # Обновление контуров через Overpass API
├── assets/                   # Стили и изображения
├── docs/                     # Локальные копии условий и датасета
├── tests/                    # Проверки модели, интерфейса и интеграций
├── .streamlit/config.toml    # Настройки Streamlit
├── .env.example              # Образец настройки API-ключа
├── requirements.txt
├── requirements-dev.txt
└── requirements-lock.txt
```

**Взаимодействие компонентов:**

```text
Действия пользователя в Streamlit
              ↓
      Проверка и изменение плана
              ↓
      Расчёт в src/model.py
              ↓
    Карта, таблицы, графики, JSON
              ↓
  По запросу — объяснение через OpenAI
```

Расчётная модель отделена от интерфейса и сетевых запросов. Состояние планов и AI-отчётов хранится в текущей сессии Streamlit.

## 6. Установка и запуск

### Требования

- Python 3.12.
- `pip`.
- Браузер.
- Интернет для установки зависимостей, AI-запросов и уличной подложки карты.

После распаковки архива откройте терминал в папке `hackalem ai`.

**Перейдите в папку симулятора:**

```bash
cd astana_simulator
```

Все следующие команды выполняются внутри неё. Корневой `app.py` архива запускает другую версию приложения.

### Windows / PowerShell

Создайте новое виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запустите приложение:

```powershell
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py
```

Если в архиве уже есть `.venv`, используйте новое окружение, созданное на вашем компьютере.

### Linux / macOS

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run streamlit_app.py
```

После запуска откройте [локальное приложение](http://127.0.0.1:8501).

### Подключение AI-разбора — необязательно

Создайте файл `.env` в папке `astana_simulator` по образцу `.env.example`:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI
```

Перезапустите приложение и нажмите **«Получить AI-разбор»** для допустимого сценария.

Переменная окружения `OPENAI_API_KEY` имеет приоритет перед значением из `.env`. Не публикуйте файл с ключом.

Без ключа доступны расчёты, графики, работа со сценариями и JSON-экспорт.

## 7. Как проверить решение

### Контрольный сценарий для жюри

1. Запустите приложение.
2. Выберите режим **«Каталог мероприятий»**.
3. Нажмите **«Загрузить пример»**.
4. Проверьте состав плана:

| ID | Мероприятие | Район | Стоимость, ед. |
|---|---|---|---:|
| M7 | Школа + детсад | Нура | 24 |
| M8 | Центр семейного здоровья / поликлиника | Нура | 20 |
| M10 | Освещение и камеры Safe City | Нура | 12 |
| M12 | Цифровая платформа обращений | Весь город | 14 |
| M5 | Перевод частного сектора на чистое топливо | Сарыарка | 25 |

5. Нажмите **«Запустить симуляцию»**.
6. Откройте вкладки **«Карта Астаны»** и **«Результаты»**.

Ожидаемые результаты:

| Показатель | Значение |
|---|---:|
| Расходы | 95 ед. |
| Остаток бюджета | 5 ед. |
| Исходный Score | 52,55768 |
| Score сценария | 56,54307 |
| Score в интерфейсе после округления | 56,54 |
| Показатели ниже 40 после изменений | 0 |

В сценарии срабатывает синергия **M10 + M12**: дополнительный бонус к безопасности улиц в Нуре.

Для экспорта раскройте блок **«Штаб советников · OpenAI»** и нажмите **«Скачать сценарий и отчеты · JSON»**. Подключать AI для экспорта не требуется.

### Проверка ограничений

- Попробуйте добавить шестое мероприятие: приложение должно заблокировать действие.
- Удалите одну меру: итоговый расчёт, AI-разбор и экспорт должны стать недоступны до завершения плана.
- В режиме распределения бюджета задайте сумму больше 100 единиц: приложение должно показать превышение бюджета и заблокировать расчёт.
- Установите все пять слайдеров в ноль: результат должен совпасть с исходным Score.

### Автоматические тесты

Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Linux / macOS:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

В проекте предусмотрены тесты расчётной модели, бюджетных ограничений, конфликтов, синергий, географии, интерфейса и обработки AI-запросов. API-тесты используют подменённый транспорт и не требуют реальных запросов к OpenAI.

## 8. Данные и интеграции

### Учебный датасет

Исходные показатели, доли населения, веса, стоимость и эффекты мероприятий заданы в `src/data.py`.

В проекте сохранены:

- `docs/case.md` — условия кейса;
- `docs/dataset-source.md` — описание датасета и правил расчёта.

Модель содержит **пять районов и десять показателей на район**. Все показатели ориентированы одинаково: большее значение означает лучшее состояние.

Интерфейс использует условные единицы бюджета:

```text
1 единица = 10 000 000 ₸
100 единиц = 1 000 000 000 ₸
```

Во внутренних расчётах и JSON денежные суммы представлены в тенге.

### География

Контуры районов сохранены локально в `data/astana_districts.geojson`. По метаданным проекта они получены из OpenStreetMap через Overpass API.

Географические данные: © OpenStreetMap contributors, лицензия **ODbL 1.0**. Атрибуция отображается под картой.

Обычный запуск читает готовый GeoJSON. Для обновления геометрии предусмотрен скрипт:

```powershell
.\.venv\Scripts\python.exe scripts/fetch_districts.py
```

Обновление требует доступа к интернету.

### Внешние сервисы

| Сервис | Назначение |
|---|---|
| OpenAI API | Формирование текстового AI-разбора по данным сценария |
| CARTO | Уличная подложка карты |
| Overpass API | Обновление локальных контуров OpenStreetMap |

Подложку улиц можно отключить. Геометрия районов хранится в проекте отдельно от неё.

## 9. Ограничения текущей версии

- Данные учебные и синтетические; интеграции с актуальной городской статистикой нет.
- Используются пять районов кейса. Карта не претендует на полноту текущего административного деления Астаны.
- Каталог ограничен 14 заранее заданными мероприятиями.
- Эффекты, цены, лаги и синергии фиксированы в коде.
- Режим слайдеров использует авторскую модель с убывающей отдачей. Её коэффициенты не откалиброваны на реальных данных.
- Два режима используют разные модели воздействия; их результаты следует сравнивать внутри соответствующего режима.
- Автоматический поиск оптимального плана не реализован.
- Учётных записей и постоянной базы сценариев нет. Для сохранения результатов предусмотрен JSON-экспорт.
- AI-разбор зависит от API-ключа, доступности модели и квот внешнего сервиса. Его текст может содержать ошибки.
- Карта и AI используют внешние сервисы для отдельных возможностей; локальная расчётная модель работает независимо от AI.
